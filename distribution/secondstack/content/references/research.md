Use the knowledge tools available in this run; a routing label in brand.json is
only a label. Read relevant Product Overview/Source Registry documents and current
official topic pages. Status dates describe historical checks, not this run's
reading. If Collections are unavailable, user-supplied and current official
sources can provide evidence; leave out claims you cannot support.

Before scripting, save episode RESEARCH.md using the research template. Record the
actual Collection document/revision/date, URL/section, checked date, supported
claim, conditions, permissions, scope, limitations, conflicts and omissions. No
fixed source quota applies. An index or brandkit is not detailed feature evidence.
Resolve material conflicts with the human and omit unsupported optional claims.
Demo values are not customer results. Real UI comes from your own capture in a
demo account, from the user, or is rebuilt in HTML from screenshots and docs.
Recheck pricing, limits, availability and prerequisites before drafting and again
before delivery/SEO when they may have changed. Record the exact section, date
and effect on the claim. Reopen research when a script revision adds a factual claim.

Use selected product's optional Content Machine URL from brand.json only when
relevant. Read minimal material, record observed L-code/permalink/read depth and
fact checks; no edits, private bulk copying or transferred browser sessions.
Record whether you read a card or followed its link to the full brief. Use only
observed links and flag missing historical source material as unavailable.
If an optional board cannot be read, continue with the other evidence. Post
approval is not script approval; scheduling is not publication.

Use the latest selected product Collection and its source statuses. Updated
registries may include topic-specific documentation for all four products; do not
assume a product lacks documentation from an older package summary. A registered
read status records the registry author's prior check, not this run's reading or
live feature verification. Read relevant current sources and retain route,
permission, configuration, validation and pricing limitations before claims.
