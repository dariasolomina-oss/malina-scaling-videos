# MVP S2: state, approvals, local versions, and audio

Python >=3.10, standard library only; `requirements-s2.txt` requires no package installation.
Run all commands from the repository root. `episode.yaml` contains JSON, a valid
subset of YAML. This CLI does not read general indentation-based YAML.
Schemas and limitations: [schemas](../schemas/README.md).

## Output language policy

All newly generated repository content, documentation, scripts, video voiceovers,
captions, and YouTube outputs must be English-only. Use `language=en`; no other
language tags are allowed by this policy. Existing Russian conversation history
may remain unchanged. This is an output requirement, not a claim that every CLI
or schema enforces it automatically. Audio codecs, MP3 metadata, and timings do
not identify the spoken language or prove that speech is English; a human must
verify the actual speech separately.

## Creation and lifecycle

```sh
python3 engine/scripts/episode.py create episodes/demo --id demo --title 'LakeSentry demo' --language en
# A human/editor fills in episodes/demo/script.md (UTF-8).
python3 engine/scripts/episode.py status episodes/demo
python3 engine/scripts/script_check.py episodes/demo/script.md --max-words 180
# ONLY after an actual explicit human decision, not an agent acting on their behalf:
python3 engine/scripts/episode.py approve episodes/demo script --human 'Reviewer Name' --confirm
python3 engine/scripts/episode.py transition episodes/demo voice
# An authorized connector response is supplied separately, not generated by this CLI.
python3 engine/scripts/voice_elevenlabs.py episodes/demo /path/to/connector-response.json --authorized-connector-response
python3 engine/scripts/episode.py transition episodes/demo render
# A separate guarded renderer creates episodes/demo/media/video.mp4.
python3 engine/scripts/episode.py transition episodes/demo review
# A human actually watches the video and makes a decision:
python3 engine/scripts/episode.py approve episodes/demo video --human 'Reviewer Name' --confirm
python3 engine/scripts/episode.py transition episodes/demo publish_ready
# After actual external publication, not as a substitute for publication:
python3 engine/scripts/episode.py transition episodes/demo published
```

Strict sequence:
`topic → script → script_approved → voice → render → review → video_approved → publish_ready → published`.
Only `approve`, not `transition`, sets `*_approved`. A change to the script bytes
is detected on the next access, increments the revision, clears both approvals,
and returns the episode to `script`. An approval records the script hash,
revision, name, explicit confirmation, and UTC timestamp. Changing or deleting the
video clears video approval, returns the episode to `review`, and blocks packaging.
Empty scripts and videos cannot be approved. Consequently, `status` may update
state; it is not a read-only operation.

A name plus `--confirm` is a local attestation record, **not identity verification**.
Do not fabricate approvals or supply a person's name without their decision.
State files are trusted local files: manual editing can bypass the workflow.
The MVP has no signatures, IAM, locks, or protection against concurrent writes:
use one writer per episode and no concurrent edits during a production operation.

`transition` changes state but does not invoke TTS, a renderer, a packager, or an upload.
A production integration must call `episode.require_production(path, 'voice'|'render'|'package')`
**before the side effect**. Voice/render are prohibited without script approval;
packaging also requires video approval. The offline voice parser already uses
this guard. Existing shell/Node render commands are not intercepted by this
Python module: without guard integration, they must not be considered a safe
production path. `publish_ready` means packaging is permitted, not that a finished
archive exists.

## Isolated temporary directories

`episode.work_dir(path)` creates a unique `episodes/<id>/work/run-*` directory for
each run. The caller removes it in `finally`; the voice parser does this itself.
Temporary data is excluded from snapshots. Persistent media resides in `media/`.

## Local media storage and restoration

```sh
python3 engine/scripts/episode.py version episodes/demo --storage /path/to/local-s2-storage
# The command returns a version UUID. Restore only into a NEW directory:
python3 engine/scripts/episode.py restore episodes/demo-restored --storage /path/to/local-s2-storage --version UUID_FROM_PREVIOUS_COMMAND
```

`LocalDirectoryStorage.version/restore` is a test filesystem adapter; **no external
storage is connected**. Episode and storage directories must not overlap. A version
includes all persistent text and media, plus a manifest with SHA-256 hashes and
sizes. All paths and checksums are validated before writing; symlinks, absolute
paths, `..` paths, and backslash paths are rejected. Restore does not overwrite an
existing directory and removes incomplete output on failure. Store versions outside
git and outside the episode. A successful restore clears current approvals,
increments the revision, and requires a new human review; historical records remain
only as an audit trail. A checksum is not a signature and does not prove authorship.

## Supplied timings and offline ElevenLabs response

```sh
python3 engine/scripts/timings.py words.json episodes/demo/timings.json --source words
python3 engine/scripts/timings.py whisper-verbose.json episodes/demo/timings.json --source whisper
python3 engine/scripts/timings.py connector-response.json episodes/demo/timings.json --source elevenlabs
```

`words`: an array or `{"words":[{"text":"Hello","start":0,"end":0.4}]}`.
Whisper: only previously supplied verbose JSON with top-level `words`; `word` is
supported in place of `text`. No transcription or segment-to-word interpolation
is performed. The ElevenLabs adapter accepts supplied `alignment` or
`normalized_alignment`: `characters`, `character_start_times_seconds`, and
`character_end_times_seconds`. Whitespace defines word boundaries; no forced
alignment or accuracy assessment is performed. Finite numbers, positive word
durations, and no overlaps are required. Output: `schema_version`, `unit=seconds`,
`source`, `accuracy=not_verified`, and `words`. A human must separately check quality
and correspondence to the actual audio.

`voice_elevenlabs.py` **makes no network calls**, reads no raw keys, and uses no apps.
No authorized connected integration is available here. It only imports an already
obtained, legitimately authorized connector response: `audio_base64` plus alignment.
An explicit authorization flag and current script approval are required. Base64
and timings are validated before writing. The output `media/voice.audio` uses a
neutral extension: the codec is not inferred, and this parser does not establish
whether the audio bytes are valid or playable. The connector must supply the format
separately; the parser does not present test bytes as real audio. Neither these
checks nor supplied English text establish that the audio contains English speech.

## Checks

```sh
python3 engine/scripts/doctor.py --path .
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_*.py' -v
```

Doctor reports tool presence, Python, and disk bytes. The CDP check only reports
whether one of `CDP_URL`, `CDP_ENDPOINT`, or `BROWSER_CDP_URL` is present, without
its value; it does not launch a browser, test connectivity, or print credentials
or environment variables. Machine script checks cover empty content, word budget,
placeholders, and control characters. Editorial review always remains `pending`:
facts/claims, tone, delivery, and rights do not receive machine approval.
